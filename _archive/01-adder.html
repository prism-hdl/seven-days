七日创造 · 第一日 · 光 · 第 1 集

从一颗加法器开始

第一天，程序员说：要有光——硬件开发的两条路（RTL 与 SystemC/TLM）各写一遍，同一份电路、两份代码，行为等价靠人盯。Prism 把这两条并成一条：一份源码，同时下降为可综合 RTL 与 TLM 模型，加一路 Python 黄金参考做独立对撞。第一集把这份"同源"落到最小可行示例——一颗 32 位加法器。

module Signal<u32> @schedule run / --cosim

为什么要有光

"起初，地是空虚混沌，渊面黑暗。"

黑暗不是没有工具——恰恰相反，硬件开发有两条割裂的路：

RTL 路径 · Verilog / SystemVerilog / VHDL
周期精确、可综合、可流片——但表达冗长，算法与微架构缠在一起；一份 FIR 想改流水级，得动 40 处 wire / reg / mux。
系统建模路径 · SystemC / TLM
事务级、快数个数量级，适合架构探索与黄金参考——但不可综合；与最终 RTL 的一致性全靠人工维护。
HLS · 只补了一半
"算法 → RTL" 能做，但它吃的 SystemC 输入是可综合子集——产不出用于架构探索的 TLM 快模型；反过来，手写 TLM 也无法综合。同一个电路仍需两份代码，两份都要各自演进。

问题的核心不是语法旧，而是：同一个硬件被写了两遍，两遍的行为等价没有保证。

Prism 的答案：一份源码，三条下降通路

名字 Prism（棱镜）就是这张图——一束算法的光，经编译折射成两道光谱，再用第三个棱面独立验收：

算法层 + 调度层
module 写"做什么"
@schedule 写"怎么做"
→ RTL
SystemVerilog
可综合、可流片
→ TLM
SystemC / C++
架构探索快模型
→ golden
Python 独立解释器
第三方对撞

三方 cosim 各抓一类 bug：RTL vs golden 抓 RTL 后端下降错；RTL vs TLM 抓时序抽象契约违反；golden vs 独立 ISS 封住"前端共性 bug 三方互查不出"的死角。这一集我们先把 RTL vs golden 这条路跑通——--cosim。

为什么这一日第一集落在加法器

"一份源码 → 三条通路"听起来宏大；能跑起来才是它的第一个证据。加法器不依赖复杂协议、没有时序陷阱，却能同时展示 module / 端口 / 组合赋值 / Signal<u32> / run 五件事——20 分钟就能让 Prism 的三条下降通路第一次同拍发出同一个数值。

这就是第一日的第一行"光"。

32 位加法器

三个 32 位无符号端口——两个输入 a、b，一个输出 sum——和一句组合赋值 sum = a + b。这就是一个加法器的全部。

prism adder.prism 
module adder {
    in  a   : Signal<u32>
    in  b   : Signal<u32>
    out sum : Signal<u32>

    sum = a + b
}

@schedule adder {
    bitwidth  : { data:32 }
    pipeline  : 1 stage
    storage   : none
    interface : a, b, sum = Signal
    reset     : async_low
    clock     : 100 MHz, domain = single
    resource  : none
    latency   : 1 cycle
}

design adder_top {
    dut : adder
}

run adder_check of adder_top {
    stim : {
        a, b = {
                     0,          0,
                     1,          2,
                   100,        200,
            2147483647, 2147483647,    // 2^31-1 + 2^31-1 = 2^32-2
            4294967295,          1,    // 回绕：2^32-1 + 1 → 0
        }
    }
    until : end of stim
    show  : { a, b, sum }
}

代码解读

算法层 · module adder

  • module adder { ... } 定义一个模块，内部声明端口和逻辑。
  • Signal<u32>：32 位无符号信号端口。u<N> 是无符号、i<N> 是有符号；Prism 的 + 按端口位宽自动截断（u32 加满 2^32 回绕到 0）。
  • sum = a + b：组合赋值，描述输入到输出的函数关系。Prism 会推导出 a + b 的位宽是 32，赋给 32 位 sum——不需要手写位宽表。

调度层 · @schedule adder

@schedule 补齐 7 项 G1~G7 元数据，告诉编译器"这个模块如何下降到 RTL"：

  • interface : a, b, sum = Signal——三个端口全部按 Signal（裸电平）协议对外，无握手。
  • storage : none——没有寄存器，纯组合逻辑。
  • pipeline : 1 stage / latency : 1 cycle——一拍算完。

顶层例化 · design adder_top

design 用来把模块实例组装成完整电路。本集只有一个模块，dut : adder 就够；后续章节会用它串多模块。

仿真入口 · run adder_check

  • stim：一张激励表——列名 a, b 只在列头写一次，每两个值一拍（换行只是排版），共 5 拍。
  • until : end of stim：跑完这 5 拍就停。
  • show：观测这三列，逐行打印。

运行

bash shell 
cd /Users/zhuzg/works/soc
python3 $PRISM_HOME/frontend/prism.py run \
    prism/docs/blog/examples/adder.prism --cosim
▸ terminal
cycle a b sum 0 0 0 0 1 1 2 3 2 100 200 300 3 2147483647 2147483647 4294967294 4 4294967295 1 0 # stop: end of stim (5 cycles) [run --cosim] ✅ PASS: adder_check golden == RTL 仿真（5 拍 × 3 列全等）

表头首列 cycle 是隐式拍号，其余三列按 show 声明序。对照手算：

cycle a b sum 校验
0000✓ 零
1123✓ 小整数
2100200300✓ 中等值
32³¹−12³¹−12³²−2✓ 满载不溢出
42³²−110↺ 无符号回绕
第 3、4 拍的两个边界

第 4 拍是满载——两个 2³¹−1 相加刚好把 sum 打到 u32 的最高可用值（4294967294 = 2³² − 2）；第 5 拍回绕——2³²−1 + 1 在 32 位无符号下落到 0。Prism 的加法和 Verilog 语义一致，都是位宽截断。这一点在跨语言对接时要记住。

--cosim 抓的是什么

如果只跑 run（不带 --cosim），Prism 用内置的 Python 参考模型（golden）出结果——这是"编译器自证"。加上 --cosim，编译器把模块下降成 SystemVerilog、调用 iverilog 真跑一遍，把 SV 侧的观测序列和 golden 侧逐拍逐列比对；两边全等才打 PASS。

这一步同时钉住了两个后端：golden 求值器与 RTL 生成器——回归时任何一个出错，--cosim 会立刻指出是哪一拍哪一列分歧。

生成的 RTL 长什么样

prism.py gen-rtl 把 .prism 下降到可综合的 SystemVerilog：

bash shell 
python3 $PRISM_HOME/frontend/prism.py gen-rtl \
    prism/docs/blog/examples/adder.prism -o /tmp/adder.sv

/tmp/adder.sv 里 adder 模块本体的核心部分（去掉 clk/rst 与顶层网表包装）：

systemverilog adder.sv 
module adder_rtl #(parameter int DW = 32)(
  input  logic clk,
  input  logic rst_n,
  input  logic [32-1:0] a,
  input  logic [32-1:0] b,
  output logic [32-1:0] sum
);

  // [P7] 组合输出 / 局部 wire 赋值
  assign sum = (a + b);

endmodule
Prism ↔ SystemVerilog 对应

Signal<u32> 就是 logic [31:0]；sum = a + b 就是一条 assign。Prism 帮你把端口位宽、时钟复位分发、顶层网表包装全部生成，但电路核心和你手写的等价。

小结

这一集我们做了三件事：

  1. 用 Prism 写了32 位加法器：3 个 u32 端口，一句 sum = a + b。
  2. 用 run 段声明 5 组激励，覆盖普通值 / 满载 / 回绕三类边界。
  3. 用 --cosim 把 golden 参考模型 与 iverilog 仿真 SV 逐拍对撞，一次同时验证组合语义实现和 RTL 后端下降。

下一集，我们讲 Prism 的类型系统——u<N> / i<N> / bool、位宽推导规则、以及为什么 1 位有符号 i1 只能取 {-1, 0}。会用类型系统把这一集的加法器扩到带符号版本，观察溢出与回绕的语义差。

练习

  1. 把端口从 Signal<u32> 换成 Signal<i32>，同时把 stim 表里最后两行的 4294967295 与 2147483647 换成同位宽有符号域的值（比如 -1、-2），重跑 --cosim：sum 列现在按 i32 回绕显示。
  2. 把 stim 表里的 4294967295 换成 5000000000（超过 u32 上限），跑一次 run——报错会精确指出"向量 4 'a'=5000000000 越界（端口位宽 u32，范围 [0,4294967295]）"。
  3. 在 show 里加一列表达式 (a + b) as direct——它是表达式列，和端口列 sum 独立求值；观察两列是否逐拍相等，理解"表达式列"与"端口列"在 --cosim 里是同一份 golden、两条 RTL 通路。
