合体，不是重写

第二日造了四颗器官：pc 心跳、regfile 与 ram 记忆、alu 活动、decoder 理解世界。每一颗都有自己的 run 块、自己的手算期望、自己的 --cosim。

今天的活是把它们放进同一具身体。注意是放，不是改——第二日的五颗模块（pc / regfile / alu / ram / decoder）原样搬进 iu.prism，几乎一字未动。唯一的例外只有一处：

prismiu.prism · decoder（第 8 集 vs 今天）
// 第 8 集：只有 R 型与 I 型有 ops，其余形态借用 ADD 通路去算地址
alu_op  = (is_r | is_i_alu) ? alu_op_r : 0

// 今天：分支也借 ALU 做比较——beq/bne 走 SUB（结果为 0 即相等），
// blt/bge 走 SLT，bltu/bgeu 走 SLTU
alu_op_b = match funct3 { 0 => 1, 1 => 1, 4 => 7, 5 => 7, 6 => 9, _ => 9, }
alu_op   = (is_r | is_i_alu) ? alu_op_r : (is_b ? alu_op_b : 0)

就这六行。为什么第 8 集没写？因为当时没有下游要用"比较结果"这个数——分支指令拿到的 alu_op 是 0（ADD），算出来的是两个数之和，不是"谁大谁小"。

这就是"每颗器官都能单独测"的红利

合体的成本 = 接线 + 被暴露出来的缺口。四颗器官里只有一处缺口，因为每一颗的形状在设计时就是按"数据 + 控制两束水"划的。剩下的活全在顶层——而顶层不产生算法，只产生连接。

顺带说一句 ram：它一个字都没改，因为它本来就是字寻址的（addr 是 u6）。变的只是顶层的接法——pc 给的是字节地址，进 ram 之前切掉低两位。这一刀在第 6 集埋下、今天才落。

身体比零件多出来的两样东西

一、一颗只读的指令存储器

程序总得有个地方待着。照 ram 的样子去掉写口，再把程序烘焙进阵列初值，就是 im：

prismcpu.prism · 指令存储器
module im {
    in  addr  : Signal<u6>
    out rdata : Signal<u32>

    mem mem : [64] u32 = [
        0x00000093,   //  0: addi x1, x0, 0      x1 = 0
        0x00500113,   //  4: addi x2, x0, 5      x2 = 5
        0x002080b3,   //  8: add  x1, x1, x2     x1 += x2  ← 循环体
        0xfff10113,   // 12: addi x2, x2, -1     x2 -= 1
        0xfe011ce3,   // 16: bne  x2, x0, -8     若 x2 ≠ 0 → 回 8
        0x0000006f    // 20: jal  x0, 0          停机（自跳）
    ]

    rdata = mem[addr]
}

im 与 dm 是两颗独立的存储器——这就是哈佛架构：取指走一条路、访存走另一条路，所以同一拍里既能取指令又能读数据。冯·诺依曼架构共用一套，单周期核就得一拍取指、一拍访存，CPI 翻倍。

二、一张网表

这是今天的全部新语法——其实没有新语法，第一日第 3 集都讲过：design 里写实例、写 wire、写 connect。它是全篇唯一一处"六颗实例同框"的地方。

实例类型在这具身体里干什么
pcpc<T = i32>给出这一拍要取的指令地址
romim按地址吐出一条 32 位指令
ctldecoder把指令翻成一束控制位 + 三个寄存器号 + 一个立即数
rfregfile<T = i32>读两个操作数、写回一个结果（x0 由它自己硬连线）
exalu<T = i32>算结果，也顺便算出"分支成不成立"
dmram<SIZE = 64>数据访存（今天只读不写，但没有写口就不叫 CPU 了）

六颗实例、一份 design、一百二十来行——prism gen-rtl examples/day3/cpu.prism 出来的可综合 SystemVerilog 是 471 行、7 个模块（六颗器官各一个，加顶层）。

design：六颗实例、一张网表

先看实体清单与取指、译码两段。这两段几行就够——因为它们都是"一个来源扇出到多个目标"：

prismcpu.prism · design cpu_top（一）实例与取指
design cpu_top {
    // ==== 六颗实例 ====
    pc  : pc<T = i32>
    rf  : regfile<T = i32>
    ex  : alu<T = i32>
    rom : im
    dm  : ram<SIZE = 64>
    ctl : decoder

    // ==== 取指：pc → rom（组合读，同拍出指令）====
    wire iaddr : u6  = pc.addr[7:2] -> rom.addr      // 字节地址 → 字地址
    wire instr : u32 = rom.rdata -> ctl.instr

    // ==== 译码输出 → 寄存器堆读口 ====
    connect ctl.rs1 -> rf.raddr1
    connect ctl.rs2 -> rf.raddr2
    connect ctl.rd  -> rf.waddr

注意 iaddr 上那一刀：pc 给出的是字节地址（0, 4, 8, …），而 rom/ram 的 addr 是字地址。[7:2] 切掉低两位再喂进去——地址换算在顶层做，存储器只管"第几个字"。这是这一集唯一的算术直觉：单位不一致时，换算发生在边界上。

再看执行与分支。这一段是顶层的核心，也是全篇唯一一处"一个信号被两个下游同时用"：

prismcpu.prism · design cpu_top（二）执行与分支
    // ==== ALU 两个操作数 ====
    wire alu_a : i32 = rf.rdata1 -> ex.a
    wire alu_b : i32 = ctl.alu_src ? ctl.imm : rf.rdata2 -> ex.b
    wire alu_f : u4  = ctl.alu_op -> ex.op

    // ==== 分支条件：借 ALU 的比较结果，按 funct3 选"成不成立" ====
    wire f3    : u3 = instr[14:12]
    wire br_eq : u1 = ex.result == 0                  // SUB 得 0 → 相等
    wire br_lt : u1 = ex.result == 1                  // SLT/SLTU 得 1 → 小于
    wire br_ok : u1 = match f3 {
        0 => br_eq,                    // beq：相等即成立
        1 => br_eq == 0,               // bne：取反
        4 => br_lt,                    // blt
        5 => br_lt == 0,               // bge
        6 => br_lt,                    // bltu
        _ => br_lt == 0,               // bgeu
    }

    // ==== PC 下一步：分支成立 / jal / jalr 都算"载入" ====
    wire pc_load   : u1  = (ctl.is_branch & br_ok) | ctl.is_jal | ctl.is_jalr -> pc.load
    wire pc_target : i32 = ctl.is_jalr ? (rf.rdata1 + ctl.imm) : (pc.addr + ctl.imm)
    connect pc_target -> pc.target
分支没有自己的比较器

六种分支的"成不成立"，全部从 ex.result 一个数上读出来：SUB 得 0 就是相等，SLT/SLTU 得 1 就是小于。这不是省一个比较器的聪明劲儿——是语义上本来就同源：beq 判的就是 rs1 - rs2 == 0。ALU 那一颗器官（第 7 集）早就把这件事算好了，顶层只负责读它、并按 funct3 挑哪一位是答案。

最后一段：访存、写回、观测。

prismcpu.prism · design cpu_top（三）访存与写回
    // ==== 访存：字地址、写数据、读写使能 ====
    wire dm_addr  : u6  = ex.result[7:2] -> dm.addr
    wire dm_wdata : u32 = rf.rdata2 -> dm.wdata
    connect ctl.mem_ren -> dm.ren

    // ==== 非法指令：这一拍什么都不许落地 ====
    wire legal : u1 = ctl.is_illegal == 0
    wire rf_wen_eff : u1 = ctl.reg_wen & legal -> rf.wen
    wire dm_wen_eff : u1 = ctl.mem_wen & legal -> dm.wen

    // ==== 写回三选一：load 数据 / 链接地址(pc+4) / ALU 结果 ====
    wire is_link : u1 = ctl.is_jal | ctl.is_jalr
    wire wb_data : i32 = ctl.mem_ren ? i32(dm.rdata) : (is_link ? (pc.addr + 4) : ex.result)
    connect wb_data -> rf.wdata

    // ==== 观测：把 pc 与两个寄存器引到顶层 ====
    expose pc.pc as pcv
    expose rf.regs[1] as x1
    expose rf.regs[2] as x2
}

几个点值得停一下：

  • alu_b 那个三元：I 型用立即数、R 型用第二个寄存器值。这个二选一不归 ALU 管——ALU 只管算，谁递进来就算谁。选路的活留在顶层。
  • pc_target 也分两条路：jalr 的目标是寄存器值 + 立即数，其余都是 pc + 立即数。
  • wb_data 是三选一：load 取存储器的数、jal/jalr 取返回地址（pc + 4）、其余取 ALU 结果。写回口只有一条，三路数据在这里合流。
  • 三条 connect 里，dm.ren 是唯一没被 legal 门管的读使能——读不改变任何状态，不落地。

那条程序

程序必须能证明"分支跳对了"，否则这颗 CPU 只是会数数的机器。所以写的是一段真循环——算 5 + 4 + 3 + 2 + 1：

地址编码汇编作用
000000093addi x1, x0, 0累加和 x1 = 0
400500113addi x2, x0, 5计数 x2 = 5
8002080b3add x1, x1, x2循环体：和 += 计数
12fff10113addi x2, x2, -1计数 -= 1
16fe011ce3bne x2, x0, -8计数 ≠ 0 就跳回 8
200000006fjal x0, 0停机：无条件跳到自己

六条指令用到了四种形态：I 型算术（addi）、R 型（add）、B 型（bne，负立即数 -8）、J 型（jal）。第 8 集里那条负立即数的符号扩展，今天在这里第一次被真的用到——0xfe011ce3 的 B 型立即数要从 12 位拆出来、左移、再补符号。

手算一遍，只用心算就够：

拍pc 走这一拍落地的事x1x2
00 → 4addi x1, x0, 000
14 → 8addi x2, x0, 505
2–15循环五轮，每轮三拍：x1 += x2 → x2 -= 1 → x2 ≠ 0 则跳回 8… → 15… → 0
1616 → 20x2 已归零，16 处的分支不成立 → 顺行150
17+20 → 20jal x0, 0 自跳，pc 停住150

x1 最后是 5 + 4 + 3 + 2 + 1 = 15。jal x0, 0 里的 x0 是故意的：返回地址算出来了，但写进 x0 会被寄存器堆丢弃——这是第 6 集那两道硬连线的第一次实战。

读这张表的方法：看 pc 的锯齿。

  • 0 → 4 → 8 → 12 → 16：顺序取指，PC 每拍 +4。
  • 拍 3 走到 16、拍 4 却回到 8——bne 成立，PC 被"载入"了（pc_load = 1，走 target 而不是 +4）。
  • 这样的锯齿出现五次（x2 = 5, 4, 3, 2, 1 各一轮）。看着 x1 一格格往上：5 → 9 → 12 → 14 → 15。
  • 拍 15 之后 x2 归零，拍 16 那个锯齿没有了：16 → 20，顺行。
  • 拍 17 起 pc 钉在 20 不动了——jal x0, 0 每拍都把自己载入自己，CPU 进入稳定态，寄存器不再变。

三个值得看的细节

① 越界不报错，回绕

跑的时候编译器给了两条警告，都长这样：

▸ prism run 的 stderr（节选）
[run] [warn] [design cpu_top] assign 'pc_target = <expr>' 位宽不匹配： RHS 推得 33 位，wire 声明 32 位，将按 wire 位宽截断（与 RTL/golden 截断语义一致）

为什么是 33 位？pc.addr + ctl.imm 是两个 32 位数相加——加法会进位，位宽推导老实算出 33 位。但 pc_target 声明的是 i32，于是最高位被切掉。

这不是 bug，是32 位机器的物理事实：PC 加到头就回绕。真正的 whitebow 工程里同样有 12 条这样的警告，位置也都在加法上。Prism 的处理方式是：不猜——按你声明的宽度截断，然后告诉你。截断合法（语言规范明文规定），但绝不会静默。

② 一层今天不承重的门

rf_wen_eff = ctl.reg_wen & legal 这条线写着"非法指令不许写寄存器"。但如果把 & legal 删掉，--cosim 照样全绿——我试过了。

为什么？因为 decoder 的 is_illegal 只看 opcode。opcode 不认识时，所有 is_* 全为 0，reg_wen / mem_wen 本来就是 0——这一层是重复的。

那为什么留着？因为它的承重条件很清楚：当 is_illegal 从"只看 opcode"收紧到"也看 funct3 / funct7 的组合"（0x33 配 funct3 = 0b111 这种非法组合，今天会被当成 AND 默默执行掉）——那时 is_r 为真、reg_wen 为真，而这一拍不该落地，legal 就是唯一的闸。那是第五日（异常处理）要收的口子。

顺手一个反证：同一个改动，在这里不响

第 9 集把 is_illegal = known ? 0 : 1 改成 0，decoder 的测试当场喊了。今天在 cpu_top 上做同一个改动——全绿。
这不是测试退步了。是牙长在解码器那一层：CPU 顶层的 show 只看得到 pc 和两个寄存器，而"我以为我懂这条指令"这件事，在顶层没有可观测的后果。
同一个 bug，在哪一层被逮到，取决于哪一层有它的观测点。

③ 顶层也会截断，但顶层不藏

dm_addr = ex.result[7:2]——又是一次切片，跟取指那刀同源。单周期 CPU 里，地址从 pc 来、从寄存器来，都在字节尺度上；存储器在字尺度上。两处换算、两个方向，都写在顶层，一眼能数清。

"神称旱地为地，称水的聚处为海。神看着是好的。" —— 《创世记》 1:10

旱地至此露出。四颗器官此刻不是四颗躺在桌上的零件，而是一具能跑程序的身体——虽然这段程序只有六条指令。

下一集把程序换长：写一段真的算法（Fibonacci、冒泡、memcpy），看看这具身体跑起来的时候，pc 与寄存器的波形长什么样；再下一集，对它做第 9 集做过的事——把它弄坏，看测试会不会喊。

练习

  1. 让它跑更多轮。把 addi x2, x0, 5 的编码改成 0x00a00113（x2 = 10），until : for 24 cycles 改成 for 34 cycles。手算 x1 应该是多少？跑一遍对答案。
  2. 拆掉停机。把 pc_load 里的 ctl.is_jal 删掉。jal 变成"什么都不做"，pc 一拍 +4 走出那六条指令的范围（20 → 24 → 28 → 32 → …）。这条注入会被逮到，差异从拍 17 的 pcv 开始。顺手把 instr 加进 show——im 的阵列声明了 64 个字、只初始化了 6 个，越过去读出来的是零（opcode 0 = 谁都不认识），所以 CPU 不会跑飞，只是一拍一拍往前挪。
  3. 找一条逮不到的注入。把 wb_data 里的 is_link ? (pc.addr + 4) : 删掉，让 jal 的写回直接取 ALU 结果。跑 --cosim——全绿。为什么？（提示：这段程序里唯一的 jal 写向 x0，写进去也被丢。要让它响，把编码 0x0000006f 换成 0x000000ef（jal x1, 0）——x1 已经在 show 里：正确的返回地址是 24，被改坏的版本给出 0。）

第 3 题是这一集最值钱的一道：有些注入不响，不是测试写错了，是这段程序没走到那个分岔点上。第十二集会把这件事做成一道系统的工序。
