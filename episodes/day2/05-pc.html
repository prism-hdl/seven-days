四颗器官，为什么从它开始

第一日给了你语言、组装手段和一整套工具——但你还没用它造过一台机器。而直接看成品，是几万行源码一次摆在你面前：看得见结果，看不见因果。

换个走法：把一台处理器拆成四颗器官，一颗一颗造。每一颗都能单独跑、单独测，四颗都在自己内部把"数据"与"控制"两条水分开一次。等四颗都活了，再把它们合进同一具身体——就在这一天的末尾。

从 pc 开始，因为它是四颗里唯一会自己动的。其余三颗都要等别人给输入才动——pc 不用，时钟一到它就往前走。

而且它不陌生——reg + on clock 你在第二集的进程调度单元上已经写过；pc 就是这两件长出的新行为：一个候选式里的 +4 与一条 load 岔路。

一颗 pc 的全部

prismpc.prism
module pc<T: bits> {
    in  load   : Signal<u1>    // 1 = 载入 target（跳转），0 = 自增 +4
    in  target : Signal<T>     // 跳转目标地址
    out addr   : Signal<T>     // 当前 PC 值

    reg pc : T

    on clock {
        pc' = load ? target : pc + 4
    }

    addr = pc
}

全部就这些。逐行看：

  • reg pc : T——一份跨拍状态。它没有初值写法，因为"上电时 PC 应该是什么"归调度层（reset : async_low + 复位向量 0）。
  • on clock { pc' = … }——唯一的时序写法。注意右边读的是本拍的 pc，左边写的是下一拍的 pc；这就是 prime 记号的语义。
  • load ? target : pc + 4——两个候选值，一个选择子。整颗模块的全部决策就在这一个三目里。
  • addr = pc——组合输出。PC 的值一给出去，取指单元立刻能拿去查指令存储器。
为什么是 + 4？

RISC-V 基础指令定长 4 字节。所以"下一条指令"就是"当前地址 + 4"——PC 的步长是 ISA 规定死的，不是我们选的。（压缩指令集 RV32C 的指令是 2 字节变长，那时这条线就要另想办法——这也是为什么真核里 PC 的加法常常不是简单 +4。）

为什么这里没有"冻住"？

冻住（一个 en 端口，en=0 时整拍不动）是流水线的取指停顿才需要的事。单周期核每拍都要往前走，en 会恒接 1——那就不该有这根线。

白虹的单周期核（我们对照的那份）里，pc.prism 就只有 load / target / addr 三个信号，没有 en。等做流水线那天，这颗模块才会为它长出一根新端口——接口是长出来的，不是提前留的。

跑起来：五拍看全两种行为

prismpc.prism · run 段
run pc_check of pc_top {
    stim : {
        dut.load, dut.target, [dut.addr] = {
            0,   0, [  4],
            0,   0, [  8],
            1, 100, [100],   // 跳转
            0,   0, [104],
            1,   0, [  0],   // 跳回复位向量
        }
    }
    until : end of stim
    show  : { dut.load, dut.target, dut.addr }
}
▸ prism run examples/day2/pc.prism --debug
cycle dut_load dut_target dut_addr 0 0 0 4 1 0 0 8 2 1 100 100 # 跳转：addr 直接变成 target 3 0 0 104 4 1 0 0 # expect: 5/5 拍有断言 · 1 列 · 全等 ✅ [run --cosim] ✅ PASS: pc_check golden == RTL 仿真（5 拍 × 3 列全等；golden stop: end of stim (5 cycles)）

两点值得看：

  • 拍 0 的 addr 是 4，不是 0。因为观测点在时钟边沿之后——复位后第一拍，pc 已经从 0 走到了 4。（想看"还没走"的样子，得把观测点挪到边沿之前——Prism 的 run 固定在边沿后取值，这一层约定在两个后端（golden / RTL）是同一份。）
  • 拍 2 的 addr 是 100，不是 "8 再跳"。载入与自增是同一个候选式里的两条分支，不是两步；load 一拍就把顺序流掰断。

删掉那个选择子（改成恒为 pc + 4）试试：第 2 拍就对不上——期望 100，实得 12。删掉一个决策，测试必须喊——这就是最小样本。

pipeline 里只有它会"自己动"

四颗器官里，pc 的接口形状是最特别的：它唯一的输入只有控制（load / target），没有数据输入。它在端口上就已经把两条水分开了——

控制面
load · target
决定"跳不跳"和"跳到哪"
数据面
addr
唯一的输出，流向指令存储器

等它们合体时，这条 addr 线会接到指令存储器的地址口；target 会来自 ALU 算出的跳转目标；load 会来自"这一条是分支且条件成立"。一颗 pc 的接线图，就是整个控制流的形状。

小结

  • reg + on clock = 一份跨拍状态；' 左边是下一拍，右边是本拍。
  • 两种走法（自增 / 载入）写在同一个候选式里，用一个选择子切换——不是两步。
  • 整颗模块的决策只有一个三目：load ? target : pc + 4。
  • 它在端口上就是"控制进、数据出"的样子：firmament 最朴素的一个样本。
