四颗器官，为什么从它开始

第一日给了你语言、组装手段和一整套工具——但你还没用它造过一台机器。而直接看成品，是几万行源码一次摆在你面前：看得见结果，看不见因果。

换个走法：把一台处理器拆成四颗器官，一颗一颗造。每一颗都能单独跑、单独测，四颗都在自己内部把"数据"与"控制"两条水分开一次。等四颗都活了，再把它们合进同一具身体——就在这一天的末尾。

从 pc 开始，因为它是四颗里唯一会自己动的。其余三颗都要等别人给输入才动——pc 不用，时钟一到它就往前走。

而且它不陌生——reg + on clock 你在第二集的进程调度单元上已经写过；pc 就是这两件长出的新行为：一个候选式里的 +4 与一条 load 岔路。

一颗 pc 的全部

prismpc.prism
module pc {
    in  load   : Signal<u1>    // 1 = 载入 target（跳转），0 = 自增 +4
    in  target : Signal<u64>   // 跳转目标地址
    out addr   : Signal<u64>   // 当前 PC 值

    reg pc : u64

    on clock {
        pc' = load ? target : pc + 4
    }

    addr = pc
}

全部就这些。逐行看：

  • u64 钉在端口上——这台机器的地址就是 64 位，PC 和寄存器堆同口径。这里不写 <T: bits>：泛型要有第二个宽度才有意义，而这颗模块体内没有一处逻辑随宽度分岔（只有一次加法、一个二选一），加一个参数只是多备一份同一条路的样本。
  • reg pc : u64——一份跨拍状态。它没有初值写法，因为"上电时 PC 应该是什么"归调度层（reset : async_low + 复位向量 0）。
  • on clock { pc' = … }——唯一的时序写法。注意右边读的是本拍的 pc，左边写的是下一拍的 pc；这就是 prime 记号的语义。
  • load ? target : pc + 4——两个候选值，一个选择子。整颗模块的全部决策就在这一个三目里。
  • addr = pc——组合输出。PC 的值一给出去，取指单元立刻能拿去查指令存储器。

两条候选是从指令里来的

下面这段循环（第九集要跑的那条，这里只借它的地址）说清了 pc 两个候选各自的来处：

asm一段真循环
        addi x1, x0, 0      # 0x0000  和 = 0
        addi x2, x0, 5      # 0x0004  计数 = 5
loop:   add  x1, x1, x2     # 0x0008  ← 循环体
        addi x2, x2, -1     # 0x000C  计数 -= 1
        bne  x2, x0, loop   # 0x0010  ≠ 0 就回 loop
        …
  • pc + 4——顺行。基础指令定长 4 字节，所以"下一条"就是当前地址 +4：0x0000 走完是 0x0004，一路这样走下去。步长是 ISA 规定死的，不是我们选的。
  • target——跳到标号。bne x2, x0, loop 在 0x0010，它要回去的那格是 loop = 0x0008。这个数不在 pc 里，是指令带过来的：bne 的 B 型立即数是 -8，0x0010 + (-8) = 0x0008。
  • 于是 load 这一位就是"这一条要不要离开顺序流"：bne 成立、jal、jalr 都拉高它；其余指令一律顺行。

立即数怎么从指令里拆出来是第 8 集的事，把它加到 pc 上是第 9 集那根 pc_target 线。这一集只管一件事：候选式两条，选择子一位。

跑起来：六拍走完那段循环的头六拍

prismpc.prism · run 段
run pc_check of pc_top {
    stim : {
        load, target, [addr] = {
            0,  0, [  4],   // addi x1, x0, 0    —— 顺行：0 + 4
            0,  0, [  8],   // addi x2, x0, 5    —— 顺行：4 + 4
            0,  0, [ 12],   // add  x1, x1, x2   —— 顺行：8 + 4（这格就是 loop）
            0,  0, [ 16],   // addi x2, x2, -1   —— 顺行：12 + 4
            1,  8, [  8],   // bne  x2, x0, -8   —— 载入：跳到 loop = 8
            0,  0, [ 12],   // add  x1, x1, x2   —— 第二轮，又顺行
        }
    }
    until : end of stim
    show  : { load, target, addr }
}

两点值得看：

  • 拍 0 的 addr 是 4，不是 0。观测点在时钟边沿之后——复位后第一拍，pc 已经从 0 走到了 4。（想看"还没走"的样子，得把观测点挪到边沿之前；Prism 的 run 固定在边沿后取值，这一层约定在两条腿上同一份。）
  • 拍 4 之后 addr 回到 8，接着拍 5 又是 12——顺序流被掰断了一拍，然后从 loop 那格重新顺行。载入与自增是同一个候选式里的两条分支，不是两步。

删掉那个选择子（改成恒为 pc + 4）再跑：跳不动了，addr 自顾自往下走。

删掉一个决策，测试必须喊——这就是最小样本。

pipeline 里只有它会"自己动"

四颗器官里，pc 的接口形状是最特别的：它唯一的输入只有控制（load / target），没有数据输入。它在端口上就已经把两条水分开了——

控制面
load · target
决定"跳不跳"和"跳到哪"
数据面
addr
唯一的输出，流向指令存储器

等它们合体时，这条 addr 线会接到指令存储器的地址口；target 会来自 ALU 算出的跳转目标；load 会来自"这一条是分支且条件成立"。一颗 pc 的接线图，就是整个控制流的形状。

小结

  • reg + on clock = 一份跨拍状态；' 左边是下一拍，右边是本拍。
  • 两种走法（自增 / 载入）写在同一个候选式里，用一个选择子切换——不是两步。
  • 整颗模块的决策只有一个三目：load ? target : pc + 4。
  • 它在端口上就是"控制进、数据出"的样子：firmament 最朴素的一个样本。
