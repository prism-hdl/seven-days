合体，不是重写

四颗器官各自跑通了自己的测试台。这一集把它们接成一具身体：器官一行都不改，全部从第 5–8 集的文件里 import 进来。真正新写的只有两样——两颗存储器的实例，和一张网表。

只有一处缺口是合体才暴露出来的：decoder 的 alu_op 只管算术族（is_arith），分支那一族它报的是 0（ADD）——因为地址通路不需要比较。"这条分支要比什么"得由顶层补上。这一处后面讲。

prismcpu.prism · import 与实例
import "pc.prism"
import "memory.prism"
import "alu.prism"
import "decoder.prism"

design cpu_top {
    // ==== 六颗实例 ====
    pc  : pc
    rf  : regfile
    ex  : alu
    im  : ram<SIZE = 256, W = u32, A = u8>    // 指令侧：32 位字，1KB
    dm  : ram<SIZE = 256, W = i64, A = u8>    // 数据侧：64 位字，2KB
    ctl : decoder

    // ==== 取指：pc → im（异步读，同拍出指令）====
    wire iaddr : u8 = pc.addr[9:2] -> im.addr      // 字节地址 → 字地址
    wire instr : u32 = im.rdata -> ctl.instr
    wire f3    : u3  = instr[14:12]                // 分支形态要看的那三位

取指这一段有两个细节：iaddr 把 64 位的字节地址切成 8 位字地址（pc.addr[9:2]——256 个 32 位字的窗口），而 instr 仍然是 u32：这台机器数据是 64 位，指令恒是 32 位，两者不是一回事。

身体比零件多出来的两样东西

一、两颗存储器，同一份源码

第 6 集那句"哈佛 = 同一份源码例化两次"在这里兑现。指令侧 im 装 32 位字、数据侧 dm 装 64 位字，都是同一颗 ram：W 不同、容量与地址线一样。

im 是 ROM，可 ram 有写口——写口不接就是"悬空"，悬空在硬件里不是"不写"，而是浮着一个不确定电平。所以顶层把它焊死：

prismcpu.prism · 写口焊死（节选）
    wire dm_index : u8 = ex.result[10:3] -> dm.addr
    connect ctl.mem_ren -> dm.ren
    connect 0 -> im.wen                                   // ROM：写口焊死
    connect 0 -> im.wdata
    connect 1 -> im.ren
    connect rf.rdata2 -> dm.wdata

三根常量线：0 -> im.wen、0 -> im.wdata、1 -> im.ren。这跟白虹真核的 im 写法一致。

二、一张网表

design 里没有 reg、没有 on clock，只有实例、wire、connect、expose。行为都在器官里，这一层只负责"谁接到谁"。

网表：数据走一遍，控制拦一道

prismcpu.prism · 读口与 ALU 操作数
    // ==== 译码输出 → 寄存器堆读口 ====
    connect ctl.rs1 -> rf.raddr1
    connect ctl.rs2 -> rf.raddr2
    connect ctl.rd  -> rf.waddr

    // ==== ALU 两个操作数 ====
    // 第二操作数三选一：立即数 / 寄存器堆读口 2；是移位时只取立即数低 6 位
    // （imm 的其余位是 funct6 与算术标志，不是移量）。
    wire is_shift   : u1  = ctl.alu_op in [5, 6, 8]
    wire alu_b_raw  : i64 = ctl.alu_src ? ctl.imm : rf.rdata2
    wire alu_b      : i64 = is_shift ? alu_b_raw[5:0] : alu_b_raw
    connect alu_b     -> ex.b
    connect rf.rdata1 -> ex.a

    // ==== 分支借 ALU 做比较 ====
    // decoder 的 alu_op 只管算术族（is_arith），分支那一族给的是 0（ADD）——地址
    // 通路不需要比较。所以"这条分支要比什么"在顶层补一列：beq/bne 借 SUB（结果
    // 为 0 即相等），blt/bge 借 SLT，bltu/bgeu 借 SLTU。
    wire alu_op_b : u4 = match f3 {
        0 => 1,     // beq  → SUB
        1 => 1,     // bne  → SUB
        4 => 7,     // blt  → SLT
        5 => 7,     // bge  → SLT
        6 => 9,     // bltu → SLTU
        _ => 9,     // bgeu → SLTU
    }
    wire alu_f : u4 = ctl.is_branch ? alu_op_b : ctl.alu_op -> ex.op
prismcpu.prism · W 后处理
    // ==== W 型指令：结果按 32 位域解释，再符号扩展回 64 位 ====
    wire ex_word : i32 = ex.result[31:0]
    wire ex_ext  : i64 = ex_word                  // 符号扩展由类型声明负责
    wire alu_out : i64 = ctl.is_w_op ? ex_ext : ex.result

三段值得看的：

  • 移量只接 imm 的低 6 位。移位器的级数摆在那儿，硬件上就只有 6 根控制线；imm 那 12 位里的高位是 funct6 和算术标志，不是移量。
  • 分支借 ALU：alu_op_b 那张小表把 beq/bne 指到 SUB、blt/bge 指到 SLT、bltu/bgeu 指到 SLTU。ALU 不知道自己在为一条件分支服务——它只是被执行了第二次。
  • W 型指令的后处理：第 7 集说"32 位语义是指令的属性，不是运算的属性"，落地就是这两根 wire——结果截到 32 位（ex.result[31:0]）、声明成 i32 再符号扩展回 64。十条路的表一行都没多。
prismcpu.prism · 分支与 PC
    // ==== 分支条件：借 ALU 的比较结果，按 funct3 选"成不成立" ====
    wire br_eq : u1 = alu_out == 0                // SUB 得 0 → 相等
    wire br_lt : u1 = alu_out == 1                // SLT / SLTU 得 1 → 小于
    wire br_ok : u1 = match f3 {
        0 => br_eq,                    // beq：相等即成立
        1 => br_eq == 0,               // bne：取反
        4 => br_lt,                    // blt
        5 => br_lt == 0,               // bge
        6 => br_lt,                    // bltu
        _ => br_lt == 0,               // bgeu
    }

    // ==== PC 下一步：分支成立 / jal / jalr 都算"载入" ====
    wire pc_load   : u1  = (ctl.is_branch & br_ok) | ctl.is_jal | ctl.is_jalr -> pc.load
    wire pc_target : u64 = ctl.is_jalr ? (rf.rdata1 + ctl.imm) : (pc.addr + ctl.imm)
    connect pc_target -> pc.target
prismcpu.prism · 访存与写回
    // ==== 访存：dm 存 64 位字 ====
    // 这一台的 dm 一颗就是 64 位字，所以访存只有双字（LD/SD）一条路：字节地址
    // 右移 3 就是字地址，写口整字进、整字出，没有半字选择、也没有读-改-写合并。
    // 落在半个字上的访问（addr[2]=1）这一台没有对应的电路，也不去判它。
    wire dm_index : u8 = ex.result[10:3] -> dm.addr
    connect ctl.mem_ren -> dm.ren
    connect 0 -> im.wen                                   // ROM：写口焊死
    connect 0 -> im.wdata
    connect 1 -> im.ren
    connect rf.rdata2 -> dm.wdata

    // ==== 这一台不做错误处理 ====
    // decoder 会举手报 is_illegal，但顶层不拿它当门：先让程序跑通，非法编码照样
    // 读、照样写回。把"不懂"变成一次异常跳转是第五日 CSR 与陷阱那一集的事。
    connect ctl.reg_wen -> rf.wen
    connect ctl.mem_wen -> dm.wen

    // ==== 写回三选一：load 数据 / 链接地址(pc+4) / ALU 结果 ====
    wire is_link : u1 = ctl.is_jal | ctl.is_jalr
    wire wb_data : i64 = ctl.mem_ren ? dm.rdata : (is_link ? u64(pc.addr + 4) : alu_out)
    connect wb_data -> rf.wdata

访存这段只有一条路：dm 一个元素就是 64 位，所以字节地址一律右移 3 取字，整字进、整字出。落在半个字上的访问（addr[2] = 1）这台没有对应的电路，也不去判它——最小机器先把一条真程序跑通，宽度与对齐这些"更讲究的访存"留给 LSU 那一层。

写回是三选一：load 的数据 / 链接地址 pc + 4 / ALU 的结果。两个写使能直接从 decoder 接到寄存器堆与 dm，中间不设门——decoder 那根 is_illegal 在这一台里没人用。

    // 看循环与访存那几格，第九集拿同一颗 design 换镜像，看数组的六个字。

    expose rf.regs[13] as x13
    expose rf.regs[20] as x20

    expose dm.ram[1] as dm1

    expose dm.ram[5] as dm5

expose 引出来的都是跨拍状态：pc 里那个 reg、寄存器堆与 dm 里的那些 mem 格子。这一层能“看进去”的手段一共三种，边界各不相同——

端口
顶层输入 / 输出
show 里直接写名字。被 connect 占用的端口看不见——它已经不在顶层了。
wire
具名网线
design 层声明的线可以直接 show——“想给这根线起个名再盯住它”的正路。
expose
实例内部状态
只有 reg / mem 引得出来，组合信号不行：写 expose dut.y 会报 'y' 不是 reg（origin=local）；mem 需写 'inst.y[i]'。

所以要看“那格字被写成什么样”，只能 expose dm.ram[0] as dm0；要看“这一拍往寄存器堆送的是什么”，show wb_data 就够——它是 design 层的线。三种手段不是替代关系，是互补关系：端口看接口、wire 看具名中间量、expose 看状态本身。第 6 集那个 x0_raw 是同一件事：读口给 0 只能证明“读不出 x0”，“写不进”必须把阵列本身引出来才看得见。

那条程序

14 条指令：一个真循环，加上四条各自见证一件事的指令。机器码写在 run 块的 image 段里——镜像是测试台事实，不是芯片属性：同一颗 cpu_top 换个 image 就跑别的程序。

prismcpu.prism · run 块
run cpu_check of cpu_top {
    image : {
        prog : im[0:56] = [
            0x00000093,   //  0: addi x1, x0, 0      和 = 0
            0x00500113,   //  4: addi x2, x0, 5      计数 = 5
            0x002080b3,   //  8: add  x1, x1, x2     循环体：和 += 计数
            0xfff10113,   // 12: addi x2, x2, -1     计数 -= 1
            0xfe011ce3,   // 16: bne  x2, x0, -8     计数 ≠ 0 就回 8
            0x00100493,   // 20: addi x9, x0, 1      x9 = 1
            0xfff00513,   // 24: addi x10, x0, -1    x10 = -1
            0x00a48463,   // 28: beq  x9, x10, 8     1 ≠ -1：不许跳（借 ADD 就会跳）
            0x00300593,   // 32: addi x11, x0, 3     走到这里才写 → x11 = 3
            0x01f4961b,   // 36: slliw x12, x9, 31   W 型：按 32 位域算完再符号扩展
            0x4015569b,   // 40: sraiw x13, x10, 1   移量只占低 6 位：imm 的其余位不是移量
            0x00103023,   // 44: sd   x1, 0(x0)      和写进 dm[0]
            0x00003403,   // 48: ld   x8, 0(x0)      整字读回 → x8 = 15
            0x0000006f    // 52: jal  x0, 0          停机（自跳）
        ]
    }
    until : for 27 cycles
    show  : { pcv, x1, x2, x11, x12, x13, x8, dm0 }
}

逐条手算，四条见证线各盯一处：

  • x1 / x2：5+4+3+2+1 = 15，计数归零，循环与分支正确。
  • x11：28 处那条 beq x9, x10, 8 比的是 1 与 -1。要是分支借了 ADD 这条路，1+(-1)=0 就"相等"了，程序会跳到 36 而绕开 32 那条 addi——x11 停在 0。走到 3 才算顶层那张 alu_op_b 表真在做事。
  • x12：slliw x12, x9, 31——1 在 32 位域里左移 31 位就是符号位，符号扩展回 64 位得 -2147483648。不做后处理则是 2147483648。
  • x8 / dm0：sd 写进 dm 的那一格字，ld 再读回来，两列互相印证。

两个值得看的细节

① 分支不占新的运算，只借现成的

顶层那张 alu_op_b 表把六条分支映到三条现有运算上（SUB / SLT / SLTU）。ALU 的十条路没有为分支扩过一条——这也是第 7 集"不产生标志位"的另一面：比较结果就是一个数，谁用它谁自己解释。

② 这一台不做错误处理

decoder 会举手报 is_illegal，顶层不拿它当门。这不是遗漏，是先跑通：非法编码会照样读存储器、照样写回寄存器堆，机器不停。而这一位没被接走，就照第三集那条规则自己露成 cpu_top 的一根输出——想在表里看它，show 里写 is_illegal 就多出一列。把"不懂"变成一次异常跳转，需要 mtvec、需要 mcause、需要一条陷阱通路——那是第五日 CSR 与异常那一集的活，今天先不装这道门，也就不给它留一个恒接 1 的接口。

小结：一具身体，六颗实例

  • 器官一行不改，全靠 import + wire + connect——合体是连线，不是重写。
  • im / dm 是同一颗 ram 的两个实例，差别只在 W = u32 与 W = i64；ROM 的写口焊死在顶层。
  • 顶层补两样器官里没有的东西：分支的运算选择、W 结果的符号扩展。非法编码这一台不设门——第五日装陷阱时才有地方处置它。
  • 程序是测试台事实，写在 run 的 image 段；换程序不动这颗 design。
  • 27 拍跑完，golden / RTL / SystemC 三条腿逐拍逐列全等。
