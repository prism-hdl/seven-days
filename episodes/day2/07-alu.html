四颗里唯一没有时钟的

回头看已经造好的两颗：pc 有 reg + on clock，regfile 有 mem + on clock。ALU 什么都没有——它是一段纯函数：给两个数和一条选路信号，立刻出结果，不记得上一拍发生过什么。

pc
有时钟
有跨拍状态（当前地址）
regfile / ram
有时钟
有跨拍状态（存的值）
ALU
无时钟
输入变，输出立刻变——没有"上一拍"

这不是偷懒。组合逻辑是硬件的"计算"本体：它不占节拍、不需要复位、没有初值。凡是能组合做完的事，就不该拖到下一拍。

十条路，一张表

prismalu.prism
module alu<T: bits> {
    in  a      : Signal<T>      // 操作数 1
    in  b      : Signal<T>      // 操作数 2（调用方已做好移位量掩码）
    in  op     : Signal<u4>     // 运算选择 0..9
    out result : Signal<T>

    result = match op {
        0 => a + b,              // ADD
        1 => a - b,              // SUB
        2 => a & b,              // AND
        3 => a | b,              // OR
        4 => a ^ b,              // XOR
        5 => a << b,             // SLL（逻辑左移）
        6 => a >> b,             // SRA（算术右移，保号）
        7 => a < b,              // SLT（有符号比较）
        8 => T(u(a) >> b),       // SRL：先按无符号移，再用 T() 收回有符号
        9 => u(a) < u(b),        // SLTU（无符号比较）
        _ => 0,                  // 防御：op 越界给 0
    }
}

十条路，十个表达式。这条 match 编译下去就是十个并列的运算单元 + 一个多路选择器——写起来是表，长出来是电路。

两处值得停下来看的地方
  • 第 6 条与第 8 条的区别：同一个 >>，a 是有符号时是算术右移（补符号位），u(a) 转成无符号后就是逻辑右移（补 0）。-8 >> 1 = -4、u(-8) >> 1 = 2147483644——同一条指令字段，两种语义。
  • 第 8 条外面那层 T(...)：无符号移完如果不收回来，整条 match 的类型会被"污染"成无符号，第 6 条（算术右移）也一起变形。类型是跟着整个表达式走的，不是逐行看的。

还有一条：移位量不由 ALU 自己掩码。b 传进来之前，由调用方按 XLEN 掩好（RV32 取低 5 位、RV64 取低 6 位）。为什么？因为 ALU 是泛型的——它不知道自己是 32 位还是 64 位。把"几位的移位量合法"这个决定交给知道 XLEN 的那一层，ALU 才能保持纯粹。

第 7、8 两行放在一起看：同样的 a=-8, b=1，只换了 op，结果从 -4 变成 2147483644。这不是"算错了"，这是两种不同的右移。符号性不是装饰，它决定电路怎么接。

ALU 不管的那些事

一颗模块的边界，往往比它的内容更能说明设计取向。ALU 有三件事刻意不管：

  • 它不掩移位量。b 传进来之前，调用方已经按 XLEN 掩好（RV32 取低 5 位、RV64 取低 6 位）。ALU 是泛型的，它不知道自己是 32 位还是 64 位——"几位的移位量合法"这个决定，只有知道 XLEN 的那一层才有资格做。
  • 它不产生标志位。没有 zero flag、carry flag、overflow flag。RISC-V 与 x86 在这里分道扬镳：x86 的 cmp 去写 EFLAGS，之后的分支读那一堆状态位；RISC-V 的 slt / beq 直接比两个寄存器——比较的结果要么落进一个寄存器，要么当场决定跳不跳，不在 CPU 里挂一个"全局状态寄存器"。这是精简指令集最典型的一刀。
  • 它不做多周期的事。除法要试商、要移位、要重复好几拍——那是另一颗模块的活。ALU 保持纯组合，谁都能在任何一拍把它插进数据通路，不用担心"它正忙"。

第三条的代价是：CPU 里要有一颗额外的多周期单元，以及一套"什么时候可以来取结果"的握手。但那是第五日的话题——那时先有流水线，才有地方容纳"停几拍"。

小结

  • ALU 是纯组合：没有时钟、没有状态、输入变输出立刻变。
  • 十条路写成一张 match 表——写起来是表，长出来是十个并列运算 + 一个多路选择器。
  • 右移的两种语义（算术 / 逻辑）由符号性决定；T(...) / u(...) 是显式的位模式重解释。
  • 移位量的掩码归调用方——ALU 泛型，不知道 XLEN。
  • 算不完的事（除法）不塞进来：ALU 保持纯组合，多周期单元日后另立一件。

下一集造最后一颗器官 decoder——它不算数、不记事、不走路，只做一件事：理解。

练习

  1. 把第 8 条（SRL）外层的 T(...) 去掉，跑一次——哪几拍的结果变了？为什么会连累第 6 条（SRA）？（提示：类型是跟着整个 match 表达式走的。）
  2. 给 alu 加一个 cmp_zero 输出（result == 0 时为 1），用于分支判断。op 需要变宽吗？为什么？
  3. 把 alu_op 的宽度从 u4 改成 u5，@schedule 的 bitwidth 跟着改——跑一次，结果会变吗？为什么？（提示：宽度只影响能表示多少种 op，不影响已实现的那十条。）
