同一颗电路，两层写法

Prism 的第一条设计线是分层：module 只写"做什么"（数据流函数），@schedule 才谈"怎么做"（位宽、流水、存储、时钟、复位）。二者不共享语法，也不允许混。

module
算法层 · "做什么"
端口、组合表达式 x = expr、时序更新 on clock { x' = expr }、reg / mem / fsm 原语。像写数据流图。
@schedule
调度层 · "怎么做"
位宽、流水级数、存储声明、时钟频率、复位极性、资源约束、延迟。只有它知道微架构——算法层不碰。

为什么必须分开？因为 RTL 与 TLM 要的信息量不对等：RTL 需要流水级、资源仲裁、握手 FSM 这些微架构；TLM（事务级）不需要。同源双出不是对称翻译，是一个"信息注入"问题——把微架构从算法里剥出来，编译器才能给一边注入、给另一边忽略。

主角：一颗带 fsm 的饱和计数器

第二集不铺开讲语法——用一颗小模块把骨架一次摆完。它要求：数到 15 就停住不再涨（饱和），清一下从头数；还要能看见它"现在是空闲 / 在跑 / 已经满了"。

prism sat_counter.prism 
module sat_counter {
    in  en    : Signal<u1>          // 使能：非零即真
    in  clr   : Signal<u1>          // 清零：回 IDLE 并把 count 归零
    out q     : Signal<u4>          // 计数输出（4 位无符号，0..15）
    out full  : Signal<u1>          // 饱和标志
    out state : Signal<u2>          // 观测态序号

    fsm ctrl {
        states : IDLE, RUN, TOP
        reset  : IDLE

        IDLE: en     -> RUN
        IDLE: _      -> IDLE
        RUN:  clr    -> IDLE
        RUN:  full   -> TOP
        RUN:  _      -> RUN
        TOP:  clr    -> IDLE
        TOP:  _      -> TOP
    }

    reg count : u4

    on clock {
        count' = clr ? 0 : (full ? count : ((ctrl.is(RUN) & en) ? count + 1 : count))
    }

    q     = count
    full  = (count == 15) ? 1 : 0
    state = match { ctrl.is(IDLE) => 0,
                    ctrl.is(RUN)  => 1,
                    _             => 2 }
}

拆开看：算法层的五件兵器

  • 端口 · Signal<T> + 方向词 — in / out / both 显式标方向，不靠"有没有被赋值"倒推。Signal<u4> 就是 4 位无符号，Signal<u1> 是 1 位无符号（控制位首选，不是 i1——1 位补码只装得下 0 和 −1）。
  • 组合表达式 · x = expr — q = count、full = (count == 15) ? 1 : 0。输入一变输出立刻跟着变，无时钟。
  • 时序更新 · on clock { x' = expr } — '（prime）是 next-state 记号：等号右边读的是本拍值，左边写的是下一拍值。这就是 Prism 里唯一的时序写法，没有"阻塞 / 非阻塞"问题。
  • reg — 声明一个跨拍状态 reg count : u4。它在算法层只说"这是一份状态"，至于占用多少触发器、复位成什么值，归调度层。
  • fsm 原语 — 一张转移表：态: 谓词 -> 目标态。_ 是兜底（默认自环）。不用手写 if / match 编状态码——状态机的语义写在算法层，编码交给调度层。

match 与三元

两个选择器，各有各的用处：

  • 三元 cond ? a : b——二选一，链式右结合，c1 ? e1 : c2 ? e2 : e3 就是一个两级 mux，无需括号。
  • match——多路分发，_ 兜底。state = match { ctrl.is(IDLE) => 0, ctrl.is(RUN) => 1, _ => 2 } 读作"如果现在是 IDLE 就输出 0，RUN 就 1，否则 2"。
为什么 ctrl.is(RUN) 而不是 state == 1？

ctrl.is(RUN) 是编码无关谓词——它读的是"态"，不是"态的编码值"。今天编译器把三个态编成 00/01/10，明天换成独热码，源码一个字都不用改。这是分层带来的第一个红利。

调度层：八行说清微架构

同一颗模块的算法写完，微架构还没着落。下面这八行把它补上——一行不多，一行不少：

字段说什么本集取值
bitwidth数据通路位宽（可用什么精度算）{ data:4 } — 4 位
pipeline几级流水1 stage — 一拍算完
storage哪些信号真的是寄存器、几位宽count = reg, width = 4
interface端口绑定什么协议en, clr, q, full, state = Signal（裸电平，无握手）
reset复位极性async_low — 低电平异步复位
clock时钟频率与域100 MHz, domain = single
resource资源约束（对 PPA 有影响）none
latency声明延迟1 cycle

注意 storage 那一行：算法层写了 reg count : u4，调度层又写了一遍 count = reg, width = 4。这不是重复——算法层说的是"这是一份跨拍状态"，调度层说的是"它占 4 个触发器"。第一种是语义，第二种是微架构。

跑起来：从 0 数到饱和，再清回去

激励表只有两列输入（en、clr），三列期望（q、full、state）——每一行都是手算的：

prism sat_counter.prism · run 段 
run sat_counter_check of sat_counter_top {
    stim : {
        en, clr, [q, full, state] = {
            1, 0, [ 0, 0, 1],
            1, 0, [ 1, 0, 1],
            …  （中间 13 拍逐拍 +1，略）
            1, 0, [15, 1, 1],   // 饱和点：full 起效
            1, 0, [15, 1, 2],   // 再一拍，FSM 进 TOP
            0, 0, [15, 1, 2],   // en 拉低也保持
            0, 1, [ 0, 0, 0],   // clr：回 IDLE、count 归零
            1, 0, [ 0, 0, 1],   // 重新开跑
            1, 0, [ 1, 0, 1],
        }
    }
    until : end of stim
    show  : { en, clr, q, full, state }
}

写错一次：饱和那一拍

第一版我没写 full ? count : … 这个分支，直接写：

prism 错误版本 
count' = clr ? 0 : ((ctrl.is(RUN) & en) ? count + 1 : count)

结果第 16 拍 q 不是 15——是 0。数到 15 那拍，count + 1 在 4 位上回绕成 0；而 FSM 的 full 守卫要到同一个边沿之后才知道"满了"。

▸ 错误版输出（截取）
15 1 0 15 1 1 16 1 0 0 0 2 # 回绕了！ [expect] ❌ cycle 16 q: 期望 15，实得 0 [expect] ❌ cycle 16 full: 期望 1，实得 0
教训：控制管"什么时候停"，数据管"停在哪个值"

FSM 决定"我该去 TOP 了"，但数据通路仍必须自己保证不越界。两件事都要做：FSM 的状态转移负责时序语义，full ? count : … 负责数值语义。这不是 Prism 特有的坑——任何 RTL 里"边沿上同时发生的多个条件"都要这样分开想。

骨架的其余零件

上面那颗模块覆盖了最常用的一批，剩下的四件先见个面——后面写到它们时再展开：

  • mem · 阵列存储 — mem regs : i32 [32] = 0 声明 32 个字的寄存器阵列，可索引读写。第六集寄存器堆就是它。
  • 泛型 <T: Bits> — module counter<T: Bits> { out q : Signal<T> … }，实例化时给位宽 counter<T = i8>。同一份源码长出 8 位 / 32 位 / 64 位三个版本——第八集 RV64I 靠它，不用复制粘贴。
  • 协议端口 Stream<T> — 带 valid / ready 握手的三元组，用来描述有背压的流水接口。
  • 位切片与拼接 — x[7:0] 切、{a, b} 拼、{N{x}} 复制。srl() / ult() / uge() 等内建函数也在这一族。

小结 · 第一日的语法到此讲完

这一集只有一件事：空气与水要分开。

  • 算法与调度分开——module 说"做什么"，@schedule 说"怎么做"；bitwidth / storage / pipeline 这些微架构信息只在调度层出现。
  • 组合与时序分开——x = expr 是本拍函数，on clock { x' = expr } 是跨拍更新；唯一的时序写法，没有阻塞/非阻塞陷阱。
  • 状态与编码分开——fsm 写转移表，ctrl.is(S) 是编码无关谓词；怎么编、编几位，归调度层。
"神称空气为天。有晚上，有早晨，是第二日。" —— 《创世记》 1:8

练习

  1. 把饱和点从 15 改成 3——改 full = (count == 15) ? 1 : 0 里的判等值即可，同时把 stim 的期望也改成"数到 3 就停"。跑一次：FSM 在第 4 拍进 TOP，之后原地保持。三次下降全绿。
  2. 删掉 IDLE: _ -> IDLE 这条兜底边，跑 prism run——会报 fsm 'ctrl' 的态 'IDLE' 缺 `_ -> <态>` 兜底转移（最后一条须为兜底，否则该态的 guard 集不完备 → 状态卡死）。兜底不是可选项：谓词集不完备时状态机可能没有出口。
  3. 加一个第四态 ERR：en & clr 同时为 1 时进 ERR 并停住（ERR: _ -> ERR）。跑一次会看到一件有意思的事：state 走进 3 之后原地不动，但 q 仍然被 clr 清零了——清零走的是数据通路，与 FSM 无关。这正是"控制管什么时候、数据管哪个值"的又一次体现。
